# A1 scanner contract and verification

Implemented 2026-10-05. See README for invocation and STATUS for local results.
This document records the original A1 contract. Current schema 2 and default A2
behavior are documented in resource-metadata.md; use --tables-only for A1 reads.

## Input and output

`lbp-cli --game-dir PATH [--json NEW_FILE]` accepts a disc root or PS3_GAME root.
It discovers names case-insensitively, rejects case-ambiguous required inputs,
enumerates filesystem metadata, and skips nested symbolic links/reparse points.
Read handles are read-only. Do not mutate the input directory concurrently with a
scan: metadata/open checks are not a sandbox against hostile filesystem races.

Required inputs: PARAM.SFO, USRDIR/OUTPUT/BLURAYGUIDS.MAP (revision 0x100), and
one or more FARC files under USRDIR. Unsupported revisions fail explicitly.
Only SFO, MAP and archive footer/index bytes are read; resource payloads are not.
Files outside PS3_GAME are not enumerated. Updates, overlays and archive precedence
are not inferred. MAP paths are validated lexically and matched to the catalog;
they are never used directly to open filesystem files.

JSON uses schema_version 1 and milestone A1_directory_tables. Stable sorting,
relative paths and no timestamps make output independent of source-root form.
The output parent must exist and resolve outside the selected source; output must
not already exist. Buffered serialization to a temporary file, flush/sync and
no-overwrite publication protect existing files. No JSON is published after a
parse/limit failure. Console output is a summary, not an alternate JSON schema.

## What the fields mean

- build: selected SFO identity fields, with disc_declared identification basis.
- build_fingerprint/map.sha256: hashes of small SFO/MAP metadata only.
- archives: every indexed entry, original entry_index, SHA-1 identifier, offset and size.
- resources: every MAP row with original row_index, unsigned GUID as 8-digit hex,
  SHA-1 as 40-digit hex, raw timestamp, declared size, path and all location candidates.
- type_hint: extension inference; confirmed_type is null. header_status and
  dependency_status are not_inspected, even for well-known extensions.
- loose_candidates: case-insensitive path matches with size comparison, not_hashed.
- archive_candidates: SHA-1 table joins with size comparison. Indexed payload
  SHA-1s are not verified in A1. A matching hash is a candidate, not a chosen overlay.
- duplicate identifiers/aliases are retained; multiple candidates remain ambiguous.
- missing_in_selected_directory means no candidate in this particular catalog.
  It does not establish corruption or absence from a full game installation.

Counts distinguish filesystem entries, raw MAP rows, distinct MAP hashes, raw
archive entries, distinct archive hashes, aliases/duplicate GUID rows and uninspected
resources. uninspected_resources counts distinct MAP hashes; archive-only hashes
are separately counted. rows_with_unknown_extension_hint is not an unknown-magic count.

## Budgets and source provenance

Defaults: 64 MiB per MAP/FARC table, one million MAP entries and combined FARC
entries, one million enumerated filesystem entries, 16 KiB MAP path bytes.
SFO is separately capped at 1 MiB and 4,096 records. CLI exposes table/entry/file
limits; checked arithmetic and table-range validation reject excessive offsets.

Layout provenance is pinned beside readers: Toolkit d6a2ef80, FileDB::process,
FileArchive constructor, ParamSFO::build, corroborated by BCUS98245 disc metadata.
See formats.md and THIRD-PARTY-NOTICES.md. Rust readers were authored independently;
no unlicensed/decompiled implementation or original asset is bundled.

## Regression coverage

Synthetic tests cover every truncation of representative MAP/FARC/SFO structures,
unsupported MAP revision, byte/count/path limits, trailing MAP bytes, excessive
offsets/ranges, empty archives, duplicate hash/unsigned GUID preservation, raw
timestamps, archive table-only reads, both root forms, deterministic JSON, joins,
size mismatches, unsafe MAP paths, no overwrite, no output inside input and Windows
junction exclusion. Fixtures are generated by authored Rust recipes.

Local acceptance additionally compares every MAP/FARC field against the independent
Python reconnaissance probe. This is corroboration, not a community oracle: both
readers learned the layout from Toolkit. Actual Java reader parity was subsequently
established during A2; see resource-metadata.md for its scope.
The authored scripts/verify_scanner.py reproduces the full field and deterministic
JSON comparison without opening any game assets; its report must stay ignored.
No fuzzing, cross-platform CI, payload decoding or hostile concurrent mutation test
is claimed. Large generated inventories and all actual game files remain ignored.
